# Проектирование корпоративной WAN-сети

**🎯 Цели проекта**: практическое закрепление и систематизация полученных знаний в области проектирования и администрирования сетей на базе оборудования Cisco. Лабораторная работа выполнена для демонстрации навыков комплексной настройки сетевых служб, протоколов маршрутизации и политик безопасности в условиях, приближенных к реальной корпоративной среде.


## 📋 Техническое задание
1. Спроектировать и настроить сетевую инфраструктуру для двух удаленных филиалов: Офис 1 и Офис 2.
2. Обеспечить связность между пограничными маршрутизаторами офисов через магистральный WAN-канал в подсети 10.0.0.0/30.
3. В качестве протокола динамической маршрутизации для связи офисов по магистральному каналу использовать OSPF.
4. Настроить технологию NAT/PAT на пограничных роутерах для обеспечения безопасного выхода внутренних узлов локальных сетей во внешнюю среду.
5. Для стыковки с внешними сетями провайдера использовать следующие выделенные подсети: маршрутизатор Router-OFF1 — 213.234.10.0/30, маршрутизатор Router-OFF2 — 213.244.10.0/30.
6. Разграничить сетевой трафик внутри каждого офиса с помощью технологии VLAN по стандарту 802.1Q и настроить необходимые trunk-порты для передачи тегированного трафика между коммутаторами и роутером.
7. Настроить маршрутизацию трафика между подсетями на базе технологии Router-on-Stick с использованием субинтерфейсов на пограничных маршрутизаторах.
8. Спроектировать и распределить адресное пространство локальной сети Офиса 1 строго в соответствии с параметрами, указанными в таблице адресации [Таблице адресации Офиса 1](#локальная-сеть-офис-1).
9. Спроектировать и распределить адресное пространство локальной сети Офиса 2 строго в соответствии с параметрами, указанными в таблице адресации [Таблице адресации Офиса 2](#локальная-сеть-офис-2).
10. Настроить проводную сеть для стационарных компьютеров офисных работников и развернуть беспроводную сеть (Wi-Fi) для мобильных устройств сотрудников с использованием беспроводных точек доступа.
11. Развернуть и настроить DHCP-сервер в качестве отдельного сервера для автоматической выдачи сетевых параметров конечным устройствам во всех необходимых VLAN, активировать передачу параметров TFTP-сервера для автоматической загрузки конфигурационных файлов оконечными телефонными аппаратами.
13. Объединить цифровые IP-телефоны и аналоговые телефонные аппараты в одну общую телефонную сеть.
14. Настроить правила трансляции, маршрутизации и обработки вызовов для обеспечения возможности сквозных звонков IP-телефонии из одного филиала в другой.
15. Вынести интерфейсы управления коммутаторов уровней Core и Access в выделенный управляющий сегмент (VLAN 99) и настроить защищенный удаленный доступ по протоколу SSH.
16. Наложить жесткое ограничение на удаленное управление: доступ к CLI коммутаторов Core и Access должен быть разрешен исключительно со стационарного офисного компьютера администратора с IP-адресом 10.1.10.2.
17. Разработать и применить списки контроля доступа (ACL) на интерфейсах каждого маршрутизатора от несанкционированного входящего доступа в сеть извне, заблокировав неинициированный входящий трафик и сканирование из внешней сети.

## Политики безопасности 
1. **Защита управления оборудованием:** Обычным пользователям и беспроводным клиентам полностью заблокирован доступ к настройкам сети. Удаленное управление коммутаторами и маршрутизаторами разрешено исключительно с рабочего места системного администратора из сети или с другого устройства из подсети`10.[1/2].99.0/24`.
2. **Изоляция телефонной сети:** Пользовательские компьютеры и Wi-Fi устройства полностью отрезаны от подсетей IP-телефонии и шлюзов ATA. Это исключает несанкционированное вмешательство в работу голосовых сервисов и защищает телефонную сеть от лишнего трафика.
3. **Защита от внешних угроз:** Внутренний периметр обоих офисов скрыт от внешней сети провайдера с помощью списков доступа. Любые неинициированные попытки проникновения или сканирования из интернета автоматически отбрасываются маршрутизаторами.
